# 役割ごとの「次に試すもの」

`setup` スキルの手順6で読む表。

## 全員共通

| スキル | 何をするか | こう頼む |
|---|---|---|
| `/daily-schedule` | その日の予定とやることを、時間順の工程表にする | 「今日の工程表をつくって」（合言葉は「おはよう」） |
| `/mtg-prep` | 会議の前に、過去のやり取りや資料を集めて準備資料を作る | 「明日の（会議の名前）の準備資料をつくって」 |

## 役割ごとの、次の2つ

| 役割 | 1つ目 | 2つ目 |
|---|---|---|
| 経営者 | `/kabeuchi` … 考えている方針をぶつけると、反論と見落としを出す。「この方針で壁打ちしたい」 | `/weekly-report` … その週の成果・課題・判断をまとめる。「今週の振り返りをつくって」 |
| 役員・部門責任者 | `/1on1-writeback` … 1on1の内容を、メンバーごとの記録に残す。「今日の（名前）さんとの1on1を記録して」 | `/weekly-report` … その週の成果・課題・判断をまとめる。「今週の振り返りをつくって」 |
| 営業 | `/reply-draft` … 受け取ったメールへの返信を下書きする。「このメールの返信を下書きして」 | `/company-research` … 取引先を調べて、会社ごとのカルテを作る。「（会社名）のカルテをつくって」 |
| その他 | 初回の質問2で聞いた仕事の内容から、合うスキルを2つ選ぶ（あらためて質問はしない） | — |

## 最初に入れるとよい資料

| 役割 | 資料 |
|---|---|
| 経営者 | 事業計画・中期計画、経営会議や取締役会の資料、会社案内 |
| 役員・部門責任者 | 経営会議の資料、部門の目標や計画、組織図 |
| 営業 | 提案資料・サービス紹介、価格表・見積のひな形、取引先の一覧 |
| その他 | 会社案内、自分の仕事の手順書 |

入れ方: パソコンでこのフォルダを開き（Mac は Finder、Windows はエクスプローラー）、`context` → `company` → `sources` の順に開いて、資料のファイルを入れる。

入れたあと: 「資料を読んで、会社の概要を直して」と頼む。秘書が `context/company/overview.md` を下書きし、まだ確かめていない所に「（要確認）」を付けて見せる。

## 慣れてきたら

| 場面 | スキル | こう頼む |
|---|---|---|
| 返信の漏れが心配 | `/inbox-triage` | 「返信漏れてない？」 |
| 会議が終わった | `/meeting-notes` | 「さっきの打ち合わせの議事録を出して」 |
| 1日の終わり | `/daily-log` | 「今日の日報をまとめて」 |

追っている数字（売上、商談数など）があれば、`context/company/kpi.md` に書いておくと、`/weekly-report` が前の週と並べて見せる。この数字は社外に出さない。
