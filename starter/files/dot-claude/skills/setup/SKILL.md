# 初回セットアップ

配られたばかりのAI秘書フォルダを、5つの質問で「その人専用」にするスキル。終わったときに、プロフィールと会社の概要が書き込まれ、次に何を頼めばよいかを本人が分かっている状態にする。

相手は忙しい経営者・役員・営業で、エンジニアではない。質問は短く、専門用語は使わない。

## いつ使う

- `context/owner/profile.md` の先頭の `setup:` が「未完了」のとき（`CLAUDE.md` の指示で、最初の返事から始める）
- 「はじめまして」「セットアップして」「セットアップの続き」「セットアップをやり直して」と言われたとき
- 「次は何を試せばいい？」「何から始めればいい？」と聞かれたとき。この場合は、手順6「次に試すものを案内する」だけを行う

## プロフィールに書く印

| 印 | 意味 |
|---|---|
| （未記入） | まだ聞いていない |
| （あとで） | 聞いたが、本人が「あとで」と答えて飛ばした |
| なし | 本人が「使っていない」「無い」と答えた |

## 手順

### 0. 今の状態を見る

`context/owner/profile.md` と `context/company/overview.md` を読む。すでに書いてある項目は聞き直さない。「（未記入）」の項目だけを聞く。「セットアップの続き」と言われたときは、「（あとで）」の項目も聞く。

`setup:` が「完了」なのに「やり直して」と言われたら、どの項目を直したいかを聞いて、その項目だけ直す。

本人が「セットアップはしない」「今はいい」と言ったら、`setup:` を「見送り」に書き換えて終える。以後は、本人に言われるまで自分からは始めない。

### 1. はじめの一言と、最初の質問

次の3点を3行以内で伝え、同じ発言の中で最初の質問を聞く。

- これから5つ質問すること（名前と会社・役割・使っている道具・メールの署名・秘書の呼び名）
- 分からない所は「あとで」と答えれば飛ばせること
- 答えは、このフォルダの中のプロフィールに保存し、あとから直せること

途中から再開するときは、済んでいる質問を飛ばす。「続きです。あと◯つ質問します」と伝えてから、残っている最初の質問を聞く。

### 2. 5つの質問

1回に聞くのは1つ。答えをもらってから次へ進む。答えをもらうたびに、手順3の場所へ書き込む（途中で閉じても、次に開いたとき続きから聞ける）。

| # | 聞くこと | 聞き方 |
|---|---|---|
| 1 | お名前と、会社の正式名称。会社のホームページがあれば、そのURLも | 会社名は、「株式会社」が前か後ろかまで、本人が書いたとおりに写す |
| 2 | 役割。次の4つから選ぶ。兼ねていれば複数: 経営者 ／ 役員・部門責任者 ／ 営業 ／ その他 | 「その他」のときは、ふだんの仕事を一言で聞く。答えがどれに当たるか迷ったら、選択肢を示して本人に確かめる |
| 3 | ふだん使っている道具。カレンダー（Google ／ Microsoft 365 ／ その他）、メール（Google ／ Microsoft 365 ／ その他）、チャット（Slack・Teams など）、議事録をとる道具（会議を録音して文字にするもの。Teams や Zoom の文字起こし、Circleback など） | 使っていないものは「なし」と書く |
| 4 | メールの最後に付ける署名 | ふだん使っているものを、そのまま貼ってもらう。無ければ「なし」 |
| 5 | 秘書の呼び名（任意） | 「付けない」と言われたら「AI秘書」と書く |

質問2と3は選択肢から選ぶ質問なので、選択肢をクリックで選べる質問の道具（`AskUserQuestion` など）が使えるなら、それで2つまとめて聞いてよい。使えなければ、選択肢を文で並べて1つずつ聞く。

「あとで」と答えた項目には「（あとで）」と書いて、次の質問へ進む。

### 3. 書き込む

答えを次の場所に書く。

- `context/owner/profile.md`
  - 名前・会社名・役割・AI秘書の呼び名・使っている道具は、それぞれの行に書く。役割が複数なら「経営者、営業」のように読点で並べる。「その他」のときは「その他（聞いた仕事の内容）」と書く
  - 署名は「### 署名」の下に、改行もそのまま写す
  - 先頭の `updated:` を今日の日付にする（`2026-10-01` の形）
  - 「宛名や文体の好み」「判断基準・大事にしていること」「仕事の進め方」は、この5つでは聞かない。「（未記入）」のまま残す
- `context/company/overview.md`
  - 「正式名称」に会社の正式名称を書き、先頭の `updated:` を今日の日付にする
  - ホームページのURLをもらったら、その場でURLを「出典」に書く。ページを読みにいくのは、5つの質問が終わってからにする（質問の途中で読みにいくと、確認の画面が出て流れが止まる）
  - ページを読めたら、「事業・主なサービス」「お客さま」を下書きし、読み取った文の後ろに「（要確認）」を付ける
  - ページを読めなかったら、読めなかったと本人に伝え、「出典」のURLの後ろに「（まだ読めていない）」と添える

5つ終わったら、ホームページのURLをもらっていればページを読み、そのあと、項目と書いた内容を一覧で見せて、直したい所がないか聞く。一覧には、次の2つも書く。

- 「（あとで）」にした項目と、その埋め方（例: 「呼び名が決まったら『秘書の呼び名は◯◯にして』と言ってください」「署名が決まったら『署名はこれにして』と言って、署名を貼ってください」）
- 保存した場所（一覧の最後に1行で）

直したい所が無ければ、`context/owner/profile.md` の先頭の `setup:` を「完了」に書き換える。

### 4. カレンダーがつながっているか確かめる

質問3で挙がったカレンダーについて、今日の予定を1回読みにいく。

- 読めた → カレンダーがつながっていると伝える
- 読めない、または別の種類のカレンダーしかつながっていない → つなぎ方を案内する。Claude の「設定」→「コネクタ」で、使っているカレンダーを選んで接続する（本人の操作が必要。会社の管理者の許可が要る場合がある）。今は飛ばして、あとでつないでもよいと伝える

メール・チャット・議事録の道具は、ここでは試さない。それぞれのスキルを最初に使うときに確かめる。

### 5. 最初の工程表を出す

工程表は、その日の予定とやることを時間順に並べた表。「今日の工程表と、明日の工程表の、どちらをつくりますか？（あとででもかまいません）」と聞く。

- 今日か明日を選んだ → `/daily-schedule` で作る（明日の分は、「明日」を付けて呼ぶ）。カレンダーがつながっていなければ、その日の予定を貼ってもらう
- 「あとで」「いらない」→ 作らずに手順6へ進む。もう一度すすめない

この最初の1枚では、工程表だけを作る。会議の準備資料を作るかどうかの確認と、1on1の準備資料の自動作成は行わない（はじめての工程表を、質問をはさまずに見てもらうため）。準備資料の頼み方は、手順6で案内する。

### 6. 次に試すものを案内する

[first-steps.md](references/first-steps.md) を読み、次の4点を番号つきで、1点ずつ短く伝える。頼み方の言葉を先に書き、スキル名（`/kabeuchi` など）は添えるだけにする。

1. 会議の前には「（会議の名前）の準備資料をつくって」と頼めること（全員共通）
2. 役割に合わせた、次に試すもの2つとその頼み方。役割が1つなら、その行の2つ。役割が複数なら、それぞれの行の1つ目
3. 最初に入れるとよい資料と、その入れ方。役割が複数なら、それぞれの行の資料を並べる。入れ方は、手順を1行ずつに分けて書く
4. 明日からは「おはよう」で工程表が出ること

## ルール

- 聞いていないことを書かない。本人が答えなかった項目は「（未記入）」か「（あとで）」のまま残す
- 署名・会社名・URLは、本人が書いたとおりに写す。言い換えない
- 質問は5つまでにする。会社の詳しい情報は、ここで聞き出さない。資料を `context/company/sources/` に入れてもらい、そこから下書きするほうが速い
- 金額、人の評価、パスワードは聞かない。本人が書いてきても、プロフィールには書かない

## 気をつけること

1. **ホームページから読み取った内容を、確かめずに事実として書かない**: ホームページは更新が止まっていたり、同じ名前の別の会社のページだったりする。下書きには必ず「（要確認）」を付け、「まだ確かめていない所の印です」と説明して本人に見せる。本人が確かめたら印を外す
2. **カレンダーがつながらなくても、先へ進む**: 接続は本人の操作が要り、会社の管理者の許可が要る場合は、その場では終わらない。ここで止まらず、予定を貼ってもらって工程表まで出す
3. **すでに書いてあるプロフィールを、黙って上書きしない**: 「やり直して」と言われたときも、直す項目を確かめてから、その項目だけを直す
