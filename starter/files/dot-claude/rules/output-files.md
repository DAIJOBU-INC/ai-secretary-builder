# 保存先と名前の付け方

秘書が作ったものを、どこに、どんな名前で保存するかのルール。スキルに保存先や名前の決まりがあれば、そちらに従う。

## 保存先

| 作るもの | 保存先 |
|---|---|
| 工程表・日報・未返信チェック | `work/daily/` |
| 週次レポート | `work/weekly/` |
| 会議の準備資料・議事録 | `work/mtg/` |
| 返信の下書きの控え（残したいときだけ） | `work/mail/` |
| 調べものの結果 | `work/research/` |
| 記事・URLの要約 | `work/clips/` |
| 読書メモ | `work/reading/` |
| 記事・発信文の下書き | `work/content/` |
| 取引先ごとのカルテ | `context/clients/` |
| メンバーごとの記録 | `context/members/` |
| 判断の記録 | `context/company/decisions.md`（末尾に足す。前の記録は直さない） |
| 追っている数字（売上、商談数など） | `context/company/kpi.md`（社外に出さない） |
| 自分の文体のルール | `context/owner/writing-style.md` |

- フォルダが無ければ作る
- 上の表に無いものを作るときは、いちばん近いフォルダに置き、置いた場所を本人に伝える
- 作ったものは、`work/` のすぐ下には置かず、上の表のフォルダに入れる（`work/README.md` は案内用のファイル）

## 名前の付け方

- スキルに名前の決まりが無いものは、`YYYYMMDD_種類_内容.md` にする（例: `20261001_メモ_来期の方針.md`）
- 日付は、その成果物が対象にする日にする（工程表なら予定の日、議事録なら会議の日）
- 同じ名前のファイルがすでにあるときは、別の名前で作らない。工程表のように毎回作り直すものは、そのファイルを更新する（例: 前の晩に作った明日の工程表を、当日の朝に作り直す）。日報や議事録のように中身を足していくものは、上書きせず、追記するか本人に確かめる
- ファイル名に、金額と、取引先の担当者の名前は入れない
